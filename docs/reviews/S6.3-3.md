## À corriger

### 3.1 Au téléphone, un balayage vertical sur le plateau ne fait pas défiler la page et affiche un refus rouge
- **Où** : tactile, toutes les grilles, 375 et 320 px (`swipe-plateau-375.png`, grille 10).
  - `web/src/styles/app.css:64` : `.board-wrap.placing .board-scroll > svg { touch-action: none; }`.
  - Une centrale est toujours choisie à l'ouverture (2.6), donc le plateau est toujours en mode `placing`.
- **Ce qu'on voit** :
  - À 375 × 667, le plateau et ses lignes réservées occupent toute la largeur et la bande de 180 à 470 px, soit près de la moitié de l'écran.
  - Le joueur pose le pouce sur la grille pour descendre vers le carnet et les indices. La page ne bouge pas (`scrollY` reste à 0 ; le même balayage sur une carte fait défiler de 200 px).
  - Le geste est lu comme un glisser vertical : « Nucléaire à 9h, ligne 1 : la barre de nucléaire doit faire 3 à 6 créneaux. » s'affiche en rouge. Le joueur n'a rien voulu poser.
  - Si le balayage part de la bande vide au-dessus de la grille, il pose une ancre hors de la silhouette : « Nucléaire à 9h, ligne 5 : touche maintenant la case d’arrivée. ».
- **Attendu** : un balayage vertical sur le plateau fait défiler la page, sans message d'erreur. Glisser horizontalement pose toujours une barre.
- **Correctif** :
  - Quand la centrale choisie n'a qu'une hauteur possible (cas de toutes les grilles actuelles : nucléaire, gaz, TAC, import, barrage d'1 GW), passer le SVG en `touch-action: pan-y`. Le navigateur garde alors les balayages verticaux pour le défilement, et le glisser horizontal reste au jeu (une barre d'1 GW ne change jamais de ligne, cf. `rectBetween`).
  - Garder `touch-action: none` pour une pièce à plusieurs hauteurs.
  - Si `pointercancel` arrive (le navigateur prend la main pour défiler), oublier le geste sans message (`onPointerCancel` le fait déjà pour `drag`).
  - Ajouter à la liste fixe : « I42 · Balayage vertical sur le plateau · tactile, centrale à barre choisie · la page défile, aucun message de refus ».
