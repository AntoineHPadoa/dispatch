## Bloquant

### 1. Adresse e-mail professionnelle et chemin personnel dans l'historique
- **Où** :
  - Auteur et committer des 17 commits : nom `AntoineHPadoa`, adresse sur le domaine de l'entreprise. Visible avec `git log --format='%ae'`. Je ne la recopie pas ici, puisque ce rapport sera lui-même publié.
  - Chemin absolu `/Users/…/Programs/spot-elec/`, qui donne le nom du compte local :
    - dans l'arbre actuel : `docs/archive/demo-spec.md:60` ;
    - dans l'historique : `GAME-DESIGN.md:214`, présent jusqu'à `d992c1e`.
- **Pourquoi c'est bloquant** :
  - La consigne exclut les adresses e-mail et les chemins personnels.
  - Un push public expose l'historique entier, et GitHub affiche l'adresse sur chaque commit.
  - Une fois poussé, on ne peut plus le retirer proprement : forks, caches, archives.
- **Correctif**, à faire avant le premier push, dépôt distant vide :
  1. Choisir l'identité publique, par exemple l'adresse `noreply` de GitHub (`<id>+AntoineHPadoa@users.noreply.github.com`, dans Settings → Emails). La fixer pour la suite avec `git config user.email …` dans ce dépôt.
  2. Réécrire les 17 commits :
     - `git filter-repo --mailmap mailmap.txt`, avec une ligne `AntoineHPadoa <noreply> <adresse actuelle>` ;
     - ou, sans outil : `git rebase -r --root --exec 'git commit --amend --no-edit --reset-author'` (même date de commit).
  3. Dans le même passage, remplacer le chemin absolu par un chemin relatif dans `docs/archive/demo-spec.md:60`. Pour l'historique, `git filter-repo --replace-text` avec la ligne `/Users/<compte>/Programs/spot-elec/==>`.
  4. Vérifier, puis pousser :
     - `git log --format='%ae %ce' | sort -u` ne montre que l'adresse publique ;
     - `git log -p --all | grep -c '/Users/'` vaut 0.
- **Si l'humain accepte de publier l'adresse**, ce point devient sans objet. Le chemin de `demo-spec.md:60` reste alors un mineur.

## À corriger

### 1. Le premier push échoue si Pages n'est pas activé avant
- **Où** : `.github/workflows/deploy.yml:39` (`actions/configure-pages@v5`).
- **Scénario** : dépôt neuf, Pages pas encore activé. `configure-pages` échoue (« Get Pages site failed »), parce que le `GITHUB_TOKEN` ne peut pas créer le site. Le build est vert, mais rien n'est publié.
- La skill `deploy` cite bien le réglage, mais comme une vérification après coup, pas comme un préalable au premier push.
- **Correctif** :
  - avant le push : Settings → Pages → Source = « GitHub Actions » ;
  - ou, une fois le dépôt créé : `gh api -X POST repos/AntoineHPadoa/dispatch/pages -f build_type=workflow` ;
  - ajouter cette étape en tête de la section « Before pushing » de `.claude/skills/deploy/SKILL.md`, avec une ligne dans le README (« Publier »).

## Mineur

1. **Pas de favicon** : le navigateur demande `/favicon.ico`, qui répond 404. Sur Pages, c'est la racine de `antoinehpadoa.github.io` qui est demandée. Correctif : un `web/public/favicon.svg` et `<link rel="icon" href="/dispatch/favicon.svg">` (ou `%BASE_URL%favicon.svg`) dans `web/index.html`.
2. **`capture.sh` laisse des fichiers temporaires et ne marche que sur macOS.** `.claude/skills/run-app/capture.sh:17`.
   - `frame=$(mktemp -t dispatch-frame).html` crée un fichier par `mktemp`, puis en écrit un autre avec `.html` : seul le second est supprimé (2 restes constatés dans `$TMPDIR` après 2 appels).
   - Sous Linux, `mktemp -t dispatch-frame` échoue (gabarit sans `XXX`).
   - Correctif : `tmp=$(mktemp -d); frame=$tmp/frame.html; … rm -rf "$tmp"`.
3. **Dossier de captures sans rapport** : `docs/reviews/S4.4/` contient 2 PNG et un `frame-320.html` (page technique de capture, qui pointe sur `localhost:4173`), sans `S4.4.md`. Correctif : retirer `frame-320.html`, puis ajouter le rapport S4.4 ou supprimer le dossier.
4. **Poids des captures** : environ 3,3 Mo de PNG et de PDF de review dans `docs/reviews/` (le plus gros : `S0.2/full-1400.png`, 1,2 Mo) ; dépôt de 7,5 Mo en tout. C'est acceptable, mais les captures pleine page de S0.2 font doublon avec les captures par section. Correctif possible : ne garder que les captures par section.
5. **Résidu d'outil** : `docs/style-reference.html:2` contient `<meta name="claude:viewport-fit-sides" …>`, sans effet hors de l'outil qui l'a produite. Correctif : retirer la ligne (sans conséquence sur le rendu).
6. **Pas de version de Node déclarée.** La CI fixe Node 22 ; Vite 7 demande au moins Node 20.19 ou 22.12. Correctif : `"engines": { "node": ">=20.19" }` dans `web/package.json`, ou un fichier `web/.nvmrc` à `22`, pour que le poste local et la CI ne divergent pas.
