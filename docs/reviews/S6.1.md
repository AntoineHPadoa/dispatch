### À corriger

**A1. Jauge CO₂ : une rampe compte `len` cases au lieu de 2W − 2.**
- `web/src/ui/panels.ts:238` : `co2PerCell(grid, b) * b.len * (b.height ?? 1)`, non passé par `cellCount`.
- Scénario : T1 avec `co2_cap: 20`, solution posée. Le moteur compte 14 (`co2Total`), la jauge affiche « charbon 9 · tac 2 », soit 11. Avec un plafond serré, la jauge dit « sous le plafond » alors que le moteur refuse la pose.
- Correction : `co2PerCell(grid, b) * cellCount(grid, b)` ; un test jauge = `co2Total` sur une grille à rampe.

**A2. Le test de parité est sauté en silence quand `fixtures/grids` manque.**
- `web/tests/ramp.test.ts:207` : `describe.skipIf(!existsSync(FIXTURES))`. Sur `v2-ramp`, `fixtures/` n'existe pas (il vient de `v2-solver`) : la CI ne vérifie aucune parité, et rien ne le dit.
- Scénario : un écart TS/Python introduit plus tard passe la CI tant que `v2-solver` n'est pas fusionnée, ou si le dossier est déplacé.
- Correction : après la fusion de `v2-solver`, retirer le `skipIf` (échec si le dossier manque) ; d'ici là, le noter dans le rapport de fusion. Comparer aussi `errors` (pas seulement `ok`) : les messages sont déjà identiques.

**A3. Conflit à venir avec `v2-board-card` dans `board.ts` (fusion simulée).**
- `git merge-tree v2-board-card v2-ramp` : `main` fusionne sans conflit ; `v2-board-card` donne **2 conflits, tous deux dans `web/src/ui/board.ts`** :
  - en-tête du fichier (l. 4-9) : garder les deux puces (disposition fixe + contour de rampe) ;
  - pastilles au-dessus des colonnes (`barTop` / `topOf`, `board.ts:392-394` sur `v2-ramp`) : garder `topOf = geo.reach[c]` de `v2-board-card` ; le calcul `topIn` de `v2-ramp` y devient inutile (une rampe ne dépasse jamais la silhouette, donc la portée).
- Fusions automatiques sans conflit : `game.ts` (appels `barIndexAt`/`remove` avec `grid`), `panels.ts` (`mb()` à profil), `print.ts`, `app.css` (`.mb i.e` à côté des règles `--lift` retirées), `print.css`, `fr.ts`.
- Résolution essayée hors worktree : `tsc --noEmit` OK, 223 tests verts (seul `convert.test.ts` échoue, faute de `docs/archive` dans l'extraction).
- Points à surveiller à la main après la fusion : le cadenas d'une rampe (`board.ts:349-351`, calé par `topIn`) et la ligne de réserve de `v2-board-card` (`geo.reach`) ; l'aperçu de rampe (`drawRamp`) sur la nouvelle rangée d'export. Rejouer `rv9.mjs`.

### Mineur

**m1. `shape: null` : verdict différent de Python.**
- `web/src/model/grid.ts:307` : `def.shape ?? 'rect'` traite `null` comme rectangle ; Python le refuse (`pieces.C.shape: one of rect, trap, stair expected`). `allowsHeight` (`grid.ts:333`) le traite, lui, comme une rampe.
- Correction : `def.shape === undefined ? 'rect' : def.shape`, et le même test dans `allowsHeight`.

**m2. Silhouette de la feuille du jour : la solution d'une rampe est dessinée en rectangle.**
- `web/src/ui/home-art.ts:55` et `:70` : `p.row + (p.height ?? 1)`, `rect` de `p.len × hh`. Sans effet aujourd'hui (aucune grille à bulletin n'a de rampe) ; visible dès qu'un bulletin publie une rampe.
- Correction : tracer avec `cellsOf` / `skyline` + `roundedPath`, et `topIn` pour `rows`.

**m3. « barre » pour une rampe dans trois messages.**
- `fr.ts:161` « Plus de barre de charbon de 4 créneaux dans l'inventaire. », `fr.ts:413` « remplace 1 barre de charbon », `fr.ts:153` « La barre dépasse de la grille. ».
- Correction : « Plus de rampe… », « remplace 1 rampe de charbon », « La pièce dépasse… » quand la forme n'est pas un rectangle.

**m4. Indice « centrale engagée » d'une rampe : « ligne 2 » au lieu de « base ligne 2 ».**
- `fr.ts:112-113` ; voir `print-15.png`. Le libellé de pose dit déjà « base ligne 2 » (`fr.ts:289`).
- Correction : même tournure que `placementLabel` quand la pièce est une rampe.

**m5. Les tutoriels T1 et T4 annoncés au §8 de `docs/next/rampe-jeu.md` ne sont pas dans `grids.json`.**
- Cohérent avec la consigne de review (grilles chargées en local), mais la conception et le message de commit ne le disent pas. `check_unique.py` de `main` ne connaît pas les rampes : il faudra `v2-solver` (drapeau `allow_ramp`) avant de les ajouter.
- Correction : le noter dans `rampe-jeu.md` §8 (« reporté à la fusion de `v2-solver` »).

**m6. `stair` est accepté par le validateur et le moteur, mais n'a ni rendu ni geste vérifiés.**
- `web/src/model/shapes.ts:35` ; `GAME-DESIGN.md` §3 dit « pas encore dans le jeu ». Les fixtures E1–E4 passent le validateur TS. Une grille `stair` serait jouable sans avoir été regardée.
