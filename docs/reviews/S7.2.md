## 2. À corriger

### 1. Le convertisseur colle les intros des tutoriels sur toute grille de même id
- **Où** : `web/scripts/convert-grids.ts:244` (`INTRO_OVERRIDE[g.id] ?? …`) ; même risque avec `TEACHES[g.id]` (`:248`, limité aux tutoriels).
- **Scénario**, en suivant la skill `add-grid` : `spot-solver generate --mode pose --level none --cols 8 --neighbor --count 1 --seed 3` produit une grille `id: 1`. Une fois convertie, cette grille notée (`section: rated`) porte l'intro du tutoriel 1, « Pose toutes les centrales de l'inventaire… », alors qu'elle est sans inventaire. Le rapport affiche « intro rewritten », sans alerte.
- **Correctif** :
  - n'appliquer les surcharges qu'au fichier du prototype : clé `${source}:${id}`, ou un drapeau `--prototype` posé par `npm run convert` ;
  - ou les restreindre à `g.section === 'Tutoriel'` pour les ids 1 à 7, et au titre `Facile` pour l'id 8.
- **Test à ajouter** (nouveau `tests/convert.test.ts`) : exporter `convertGrid`. Convertir une grille générée d'`id: 1`, de section « Grilles », sans `intro`. Attendu : `intro` indéfinie et `teaches` indéfini.

### 2. `docs/style-reference.html` ne montre pas la STEP dans le carnet ni la légende du papier
`CLAUDE.md:47` dit « UI follows docs/style-reference.html » : un agent qui suit la référence défera donc S6.
- **STEP** : le carnet de la grille sans inventaire (`freeBook`, `docs/style-reference.html:~392`) n'a pas de ligne « STEP ▲▼ · 1 paire / paires à déduire ». L'app l'a (`panels.ts:52`, `:81-85`), et le choix du créneau se fait au toucher.
- **Papier** :
  - pied de page « note-les au-dessus des colonnes » (`style-reference.html:511`), alors que l'app dit « dans les cases sous la grille » (`fr.ts:413-415`) et dessine une rangée de cases STEP (`board.ts:459`) ;
  - pas de légende « Indices sur la grille » (`print.ts`, `slotLegend`).
- **Pose par-dessus** : la section 7 dit « Rien n'est supprimé sans action du joueur », sans décrire le remplacement.
- **Correctif** :
  - ajouter au carnet de `freeBook` une ligne `prow("STEP", "1 paire", "▲▼")` ;
  - corriger le pied de page papier en « Pompage ▲ et turbinage ▼ : note-les dans les cases sous la grille », et ajouter sous la grille papier une liste « Indices sur la grille » (une ligne courte par indice) ;
  - dans la carte « Pièces et poses » de la section 7, ajouter : « Poser par-dessus remplace les centrales couvertes, en une seule étape annulable ; une centrale engagée ne se remplace jamais. »

### 3. `GAME-DESIGN.md` §14 omet une règle que le validateur impose
- **Où** : `GAME-DESIGN.md:208`, liste « Contrôles du validateur ».
- **Problème** : la liste ne cite pas « une grille STEP publie son nombre de paires ». C'est pourtant imposé par `grid.ts:381-383` et rappelé par `CLAUDE.md:45`.
- **Correctif** : ajouter avant « dans `solution.step`… » : « une grille avec STEP publie son nombre de paires (`inventory.step` en exact, `step` d'un indice `exchanges` sinon) ; ».

### 4. `CLAUDE.md` ne donne pas les consignes de travail qu'un agent doit tenir
Un agent qui ne lit que `CLAUDE.md` sait lancer, tester, ajouter une grille, déployer, et sait que les textes sont dans `fr.ts`. Il lui manque :
- **Auteur des commits** : le dépôt est configuré avec l'adresse `noreply` (`user.email`) ; ne jamais commiter avec une autre identité, puisque l'historique est public.
- **Branche `backup-before-squash`** : locale, contient l'ancien historique, ne jamais la pousser (`git push origin main` seulement).
- **Relecture** : chaque livrable est relu par un agent distinct de son auteur ; les rapports vont dans `docs/reviews/<tâche>.md`, les captures dans `docs/reviews/<tâche>/`.
- **Clé de progression** : `dispatch:progress:v1` (`src/ui/progress.ts:23`) ; la changer efface la progression des joueurs (prévoir une migration).
- **Ce que la CI ne vérifie pas** : solveur et unicité (voir le point 5).
- **Correctif** : ajouter à la section « Git » de `CLAUDE.md` :

  ```markdown
  - Commit author: the repo's noreply address (`git config user.email`); the history is public.
  - `backup-before-squash` is a local-only branch (old history): never push it; push `main` only.
  - Every deliverable is reviewed by an agent other than its author: report in `docs/reviews/<task>.md`, captures in `docs/reviews/<task>/`.
  ```

  et à « Conventions » :

  ```markdown
  - Progress lives in localStorage under `dispatch:progress:v1`: renaming the key wipes players' progress.
  ```

### 5. La CI ne lance ni les tests du solveur ni `check_unique.py`
- **Où** : `.github/workflows/deploy.yml:32-34` (`npm ci`, `npm test`, `npm run build` seulement).
- **Scénario** : une grille modifiée à la main qui garde une solution valide mais en accepte une seconde passe `npm test` et part en ligne. Seul `check_unique.py` voit le défaut, et il n'est lancé qu'à la main.
- **Correctif** : ajouter un job `checks` avant `build`, avec `astral-sh/setup-uv`, puis `uv sync --locked` dans `solver/`, `.venv/bin/pytest -q`, et `../solver/.venv/bin/python scripts/check_unique.py` dans `web/` (environ 30 s). En attendant, l'écrire dans `CLAUDE.md`, à côté de la commande : « run it after any change to grids.json; CI does not ».

### 6. La logique STEP du jeu n'est pas testée
- **Où** : `src/ui/game.ts:362-398` (`stepTap`, `removePairAt`, `isStepCell`), dans un fichier couvert à 11 % (DOM).
- **Règles concernées** :
  - pas de pompage sur le dernier créneau (`:367`) ;
  - un turbinage strictement plus tard (`:375`) ;
  - en inventaire exact, pas plus de paires que publiées (`:368-369`) ;
  - un toucher sur une case ▲ ou ▼ retire la paire (`:340`).
- **Correctif** : extraire une fonction pure `stepTapResult(grid, state, pending, col) → {pending, state?, message}` dans `src/ui/step.ts`, et la tester dans `tests/ui.test.ts`. Scénarios sur la grille 7 :
  1. Pompage sur 21h : refus `UI.stepLastSlot`.
  2. Pompage sur 3h puis turbinage sur 3h : refus `stepTooEarly`. Puis sur 0h : refus.
  3. Pompage 3h puis turbinage 15h : une paire `{pump: 1, turbine: 5}`.
  4. Second pompage alors que la paire publiée est posée : refus `MSG.stepCount(1)`.
  5. Toucher la colonne 15h : la paire est retirée.
