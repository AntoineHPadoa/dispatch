# Add a grid

The game reads `web/src/data/grids.json`: a list of grids in the §14 format (`GAME-DESIGN.md` §14, types and validator in `web/src/model/grid.ts`). Commands run from `web/` unless stated.

## 1. Get a grid in the §14 format

**Generate** (solver, already §14): fill a lot, then pick a candidate.

```bash
cd ../solver
.venv/bin/dispatch-solver generate ../lab/lots/demo-01.json      # writes lab/candidates/demo-01.json and .stats.json
.venv/bin/dispatch-solver check ../lab/candidates/demo-01.json --id 4 --ramp   # verdict of one candidate
```

- A lot (`lab/lots/*.json`) mixes configurations (`cols` 6, 8 or 12, `neighbors`, `step`, `ramp`, `tall`, `surplus`, `co2_cap`, `stock`, `inventory`, `clue_types`, `rating`) under diversity quotas; see `solver/src/dispatch_solver/generate/lot.py`.
- Before adding a candidate to `grids.json`: drop its `lab` block, and turn `lab.bulletin` into `bulletin` with a `number` and a `published` date if it is a daily sheet. Grids with a coal ramp (`pieces.C.shape`) cannot go in until the web game knows ramps.
- The old prototype path (`npx tsx scripts/convert-grids.ts`, `npm run convert`) still rebuilds `grids.json` from `docs/archive/demo/grids-pose.json`: it overwrites hand edits.

**By hand**: copy a grid of the same kind from `grids.json` and edit it. Rules the validator enforces: 6 to 12 columns; ranks and CO₂ of §3; `pieces` and `inventory.pieces` have the same keys; legal shapes = allowed widths × allowed heights; a STEP grid publishes its number of pairs (`inventory.step` at level `exact`, an `exchanges` clue `step` at level `none`). `npm test` also checks that no price clue sits on a column with an import (§3).

## 2. Put it in `grids.json`

- A generated grid carries the id of its rank in the lot and its bulletin title: set `id` to the next free id.
- Append the object, with a new unique `id`, a `title`, `section` (`tutorial` with `intro` and `teaches`, or `rated`) and `difficulty` (from the solver: `rating` 1-4, `label`, `techniques`).
- Update the expected id list in `tests/grids.test.ts` ("has the … pose grids").

## 3. Check it

```bash
npm test                                                   # validator + reference solution vs every rule and clue
../solver/.venv/bin/python scripts/check_unique.py         # every grid: compositions=1, plus its rating
../solver/.venv/bin/python scripts/check_unique.py /tmp/one.json      # one file only
```

`check_unique.py` must print `OK: every grid is unique and deducible`. More than one composition means a missing clue; `deduction=stuck` means the grid needs guessing: add a clue (or keep a stock such as `"B": {"max_cells": 2}`) and re-run.

## 4. Play it

Start the app (skill `run-app`) and open `#/grille/<id>`; check the print sheet at `#/imprimer/<id>`. Player texts (clues, errors) come from `src/i18n/fr.ts`: a new clue shape may need a new text there.
